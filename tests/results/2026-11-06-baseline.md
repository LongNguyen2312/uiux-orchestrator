## What this means for the design

Basic routing from descriptions is already decent for a strong model. The orchestrator must
therefore add value where the baseline failed, not re-teach obvious routing:

1. **Verified compatibility facts** the descriptions hide (library versions, architecture
   requirements, required runtimes, invasive kits) → registry `requires` / `limitations`.
2. **Semantic mapping** between the user's words and a skill's own vocabulary (Impeccable
   refinement vs. redesign; Taste's "kind" routing) → registry `invoke_as` notes + conflict rules.
3. **Prerequisite checks before choosing a driver.**
4. **Evidence-based validation with explicit statuses** and tool availability checks.
5. **Handoff records.**
